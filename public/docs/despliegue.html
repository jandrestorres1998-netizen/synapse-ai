Arquitectura de Producción

Por diseño, el servidor central de SynapseAI expone tráfico HTTP en el puerto 3000 (o el definido en PORT). En entornos corporativos de producción, el servicio nunca debe exponerse directamente a internet sin un intermediario que gestione los certificados de cifrado y aplique directivas de red.

La topología recomendada sitúa un proxy inverso robusto (como Nginx o Caddy) en el perímetro del servidor o de la red interna:

  • Cifrado de extremo a extremo (TLS/HTTPS): Todo el tráfico entre las aplicaciones clientes y SynapseAI viaja cifrado mediante protocolos modernos (TLS 1.2 / 1.3).
  • Aislamiento de red: SynapseAI escucha únicamente en la interfaz local (HOST=127.0.0.1) o dentro de una red privada de Docker.
  • Terminación de certificados: El proxy inverso asume la gestión y renovación automatizada de los certificados SSL/TLS.

Configuración con Nginx

Plantilla de configuración de bloque de servidor para distribuciones Linux empresariales (Ubuntu, Debian, RHEL):

server {
    listen 443 ssl http2;
    server_name ai.su-empresa.com;

    ssl_certificate     /etc/ssl/certs/synapse.crt;
    ssl_certificate_key /etc/ssl/private/synapse.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # Límite de carga para prompts extensos o documentos
    client_max_body_size 10M;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        # Propagación de encabezados estándar de cliente y protocolo
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Soporte para respuestas en flujo continuo (streaming de tokens)
        proxy_set_header Connection '';
        proxy_buffering off;
        proxy_cache off;
        chunked_transfer_encoding on;

        # Tiempos de espera adecuados para consultas analíticas profundas
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
Ajuste de Proxies de Confianza

Al implementar Nginx o Caddy delante de SynapseAI, configure SYNAPSE_TRUST_PROXY_HOPS=1 en su archivo .env. Con este ajuste, el limitador de tasa de SynapseAI utilizará la dirección IP real del cliente reportada en X-Forwarded-For en lugar de la IP local del proxy.

Configuración con Caddy

Para configuraciones automatizadas con emisión y renovación transparente de certificados Let's Encrypt / ZeroSSL:

ai.su-empresa.com {
    reverse_proxy 127.0.0.1:3000 {
        # Desactivación de buffer para streaming inmediato de respuestas
        flush_interval -1
    }
}

Seguridad de la Bóveda de Claves (Vault)

SynapseAI custodia las claves maestras de OpenAI, Anthropic y Google cifradas en disco dentro de su almacén interno. Para garantizar un cifrado de nivel bancario en reposo:

  • Definir siempre SYNAPSE_VAULT_KEY: Si esta variable no se define en .env, el sistema opera con una clave temporal derivada del entorno local y emite alertas de seguridad.
  • Generar una clave con entropía criptográfica: Utilice al menos 32 bytes aleatorios (256 bits):
# Generar clave de 32 bytes en terminal
openssl rand -hex 32
Custodia de la Llave Maestra: Resguarde el valor de SYNAPSE_VAULT_KEY en el gestor de secretos de su organización. SynapseAI no almacena copias de recuperación externas de su clave de descifrado.

Copias de Seguridad del Libro de Auditoría

El libro de auditoría certifica formalmente qué solicitudes fueron procesadas y qué datos fueron anonimizados. Los archivos de estado residen en la carpeta data/:

  • data/audit.jsonl: Registro encadenado de transacciones firmado con SHA-256.
  • data/vault.enc: Bóveda cifrada de credenciales de proveedores.
  • data/budget.json: Contadores de consumo presupuestario y cuotas.

Para respaldar estos datos de forma consistente:

# Copia de seguridad automatizada periódica
tar -czf /backups/synapse-$(date +%Y%m%d).tar.gz -C /ruta/a/synapse data/

En despliegues con Docker, asegúrese de incluir el volumen persistente (-v ./data:/app/data) en sus políticas rutinarias de respaldo de infraestructura.

Política de Rotación de Credenciales

Para mantener una higiene de seguridad continua sin interrumpir los servicios:

  1. Claves de SynapseAI: Cree una nueva clave con el ámbito requerido (inference: o report:) en la consola de administración. Actualice las aplicaciones clientes con la nueva credencial. Tras verificar el tráfico, proceda a dar de baja la clave previa.
  2. Claves de proveedores de IA: Genere nuevas llaves en la consola del proveedor (OpenAI, Anthropic, Google) e ingréselas en SynapseAI mediante la consola web. La actualización se efectúa en memoria de forma instantánea sin requerir reinicio del servidor.

Monitoreo de Salud y Disponibilidad

SynapseAI proporciona una ruta ligera para sondas de disponibilidad (Kubernetes, AWS CloudWatch, Datadog, Uptime Kuma):

curl -s -i http://127.0.0.1:3000/healthz

Responde con código HTTP 200 OK certificando que el proceso está activo y listo para enrutar tráfico.
