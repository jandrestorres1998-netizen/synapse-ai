Guía de Instalación

Tres modalidades para poner en marcha la pasarela en su propia infraestructura: contenedor Docker, Node.js estándar o como servicio local en Windows.

Versión estable v2.0.0 · Arquitectura Multiplataforma

Requisitos mínimos del sistema

SynapseAI es una solución ligera optimizada en JavaScript. No requiere tarjetas gráficas especializadas (GPU); el motor de validación de reglas DLP se ejecuta íntegramente en el procesador convencional (CPU) con mínima sobrecarga.

  • Procesador: 2 núcleos o superior.
  • Memoria RAM: 2 GB disponibles (consumo típico del proceso: entre 90 y 180 MB).
  • Espacio en disco: 500 MB para el sistema base y dependencias, más el almacenamiento reservado para el registro de auditoría.
  • Entorno: Docker 20.10+ o Node.js 18 LTS o superior.

Método 1 · Despliegue con Docker (Recomendado)

La opción recomendada para servidores de producción y aislamiento total. La imagen se construye directamente en su equipo a partir del código fuente auditado:

# 1. Clonar o descargar el código de SynapseAI
git clone https://github.com/jandrestorres1998-netizen/synapse-ai.git
cd synapse-ai

# 2. Generar el archivo de configuración (.env)
node scripts/init_env.js

# 3. Construir la imagen y levantar el contenedor
docker compose up -d --build

# 4. Verificar el estado del servicio
curl http://localhost:3000/healthz

Si prefiere utilizar la CLI de Docker sin Compose:

docker build -t synapseai:2.0.0 .

docker run -d \
  --name synapseai \
  -p 3000:3000 \
  --env-file .env \
  -e HOST=0.0.0.0 \
  -v "$(pwd)/data:/app/data" \
  --restart unless-stopped \
  synapseai:2.0.0

Configuración de red en Docker:

Dentro del contenedor es indispensable definir HOST=0.0.0.0 para que el puerto publicado reciba conexiones desde la red externa o del host. En docker-compose.yml este ajuste ya viene preconfigurado.

Persistencia del volumen de datos:

Asegúrese de montar la carpeta local en /app/data dentro del contenedor. Allí se preservan la bóveda cifrada, el registro de auditoría y los contadores presupuestarios entre reinicios.

Método 2 · Node.js y npm

Recomendado si desea ejecutar pruebas en desarrollo o alojar el servicio directamente sobre un servidor Linux existente:

# 1. Acceder al directorio del proyecto
cd synapse-ai

# 2. Instalar dependencias de producción
npm install --omit=dev

# 3. Generar la configuración inicial
node scripts/init_env.js

# 4. Iniciar el servicio
npm start

Para mantener el servicio en ejecución continua en segundo plano, puede emplear pm2 o un servicio systemd:

# Gestión con PM2
pm2 start server/server.js --name synapseai
pm2 save
pm2 startup

Método 3 · Windows (Instalación automática como servicio)

Para oficinas y despachos que operan bajo Windows 10, Windows 11 o Windows Server y prefieren una instalación guiada sin consolas activas:

Instalador automatizado para Windows

Asistente en un clic

El paquete incluye el script instalar_servicio_windows.bat, que realiza el aprovisionamiento de manera transparente:

  1. Verifica o instala Node.js LTS mediante el gestor oficial de Windows (winget).
  2. Instala los módulos de producción en segundo plano.
  3. Configura SynapseAI en el Inicio automático del sistema para iniciar al encender la computadora.
  4. Crea un acceso directo en su Escritorio: «SynapseAI — Panel de Control».
  5. Inicia el servicio en segundo plano de manera silenciosa y abre la consola en su navegador.
Ejecutar: instalar_servicio_windows.bat

Para detener o reiniciar el servicio cuando lo requiera, utilice el script detener_servicio_windows.bat.

Verificación de Disponibilidad

Una vez iniciado el servidor, compruebe que la pasarela responde correctamente accediendo a la consola web:

Verificación en navegador: Ingrese a http://localhost:3000/app para visualizar el panel de administración.

También puede consultar el estado de la bóveda mediante terminal:

curl http://localhost:3000/api/vault/status

La respuesta indicará "status": "ready" con el esquema de seguridad habilitado.

Parámetros de Red y Conectividad

Acceso en Red Local

Por diseño de seguridad preventiva, HOST en .env está configurado inicialmente en 127.0.0.1 (solo llamadas locales).

Para permitir que otras estaciones de trabajo de su red corporativa consuman la pasarela, configure:

# En su archivo .env:
HOST=0.0.0.0
PORT=3000

Habilite el puerto TCP 3000 en el Firewall de Windows o en el enrutador corporativo, y asigne llaves con ámbito en SYNAPSE_API_KEYS.

Soberanía y Mantenimiento: SynapseAI se ejecuta como un proceso estándar en su entorno sin instalar controladores de bajo nivel. Su equipo de TI mantiene el control total sobre copias de respaldo y ciclo de vida del servicio.
